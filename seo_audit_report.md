### 10. CI/CD & Automation (SEO Pipeline)
- **Files Audited:** `.github/workflows/deploy.yml`
- **Passed Checks:** deploy matrix pins Go/Node; `TZ: Europe/Oslo`; `fetch-depth: 0`; Pages artifact upload; workflow_dispatch support.
- **Issues Found:**
  - **Issue 10.1 — Hugo version drift (`latest` beats declared pin); no clean destination**
    - **Severity:** Medium
    - **Location:** `.github/workflows/deploy.yml:57` (`hugo-version: 'latest'` ignores `HUGO_VERSION: 0.154.2` at line 24); build step `deploy.yml:81` lacks `--cleanDestinationDir`
    - **Problem:** the CI Hugo binary is whatever is newest at run time while the local environment is v0.165.0 and the declared pin is v0.154.2 — three different versions in play. Hugo changes output behavior between versions (e.g., the `jsonify`/`safeJS` encoding behavior your JSON-LD relies on). Without `--cleanDestinationDir`, any local/incremental build can ship stale pages (this audit's clean rebuild removed a leftover `/dev9b-links/` duplicate from an earlier local build).
    - **Ranking Impact:** unreproducible builds risk silently dropping fixes or resurrecting old URLs in production.
    - **Fix:**
      ```yaml
      # deploy.yml:57
      with:
        hugo-version: '${{ env.HUGO_VERSION }}'
        extended: true
      # deploy.yml:81-85
      hugo \
        --gc \
        --minify \
        --cleanDestinationDir \
        --baseURL "${{ steps.pages.outputs.base_url }}/" \
        --cacheDir "${{ runner.temp }}/hugo_cache"
      ```
      Align local Hugo to the pinned version (`hugo-version: 0.154.2` or bump `HUGO_VERSION` to 0.165.0) to match CI. Extend `setup-hugo` isn't needed — `peaceiris/actions-hugo` accepts the env var directly.
    - **Fix Type:** config
    - **Verification:** push a commit; check the Actions log prints the pinned Hugo version; diff `public/` for the presence/absence of stale files.
