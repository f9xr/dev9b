Astro Theme Pure is one of the few Astro blog themes that ships full-site search, an RSS feed, a sitemap, and generated Open Graph images without asking you to wire each one by hand. It also assumes you deploy to Vercel, and that assumption is where a GitHub Pages install gets interesting.

This guide installs the official repository, configures it, and deploys it with the official Astro GitHub Action. It also covers the one decision that decides whether your links work after deploy: which kind of GitHub Pages URL you pick.

The steps below were checked against repository version 4.1.6, which pins Astro 6.4.8. Commands use Bun because that is what the maintainers recommend, but npm, pnpm, and yarn work the same way.

## What Astro Theme Pure Ships With

The theme is a blog and documentation template built on Astro, licensed under Apache 2.0 and maintained by cworld1. The feature list on the project README is short and mostly true in practice:

- Full-site search built with [Pagefind](https://pagefind.app/)
- Sitemap and RSS feed generated by the theme integration
- Dynamic Open Graph images for each post
- Table of contents generated from headings
- Medium-style image zoom
- Ready-made components such as `Aside`, `Tabs`, `Timeline`, `Steps`, `GithubCard`, and `LinkPreview`
- A responsive layout and a demo that scores well on Lighthouse

The parts that actually save time are the boring ones. You do not write a sitemap template, you do not hand-build an OG image, and you do not bolt on a search box. That is a real head start compared with assembling those four things from separate plugins.

The catch is that the template is opinionated about hosting. It expects a server runtime, and GitHub Pages does not have one.

## Prerequisites for the Install

You need:

- Node.js 22.12.0 or newer. Astro 6 refuses to build on older versions, and odd-numbered Node releases such as 23 are not supported.
- Bun if you want the documented workflow, or npm, pnpm, or yarn.
- Git and a GitHub account.
- A repository you are allowed to enable Pages on.

If you are still choosing between static site generators, our [comparison of blogging platforms for developers](/p/best-blogging-sites-for-developers/) covers where Astro fits and where it fights you.

## Step 1: Clone Astro Theme Pure and Install Dependencies

Clone the repository and enter the folder:

```bash
git clone https://github.com/cworld1/astro-theme-pure.git
cd astro-theme-pure
```

Install dependencies:

```bash
bun install
# or
npm install
# or
pnpm install
```

Start the development server and confirm the theme runs before changing anything:

```bash
bun dev
```

Open `http://localhost:4321`. If the homepage renders, your toolchain is fine and you can start editing.

### Create Your First Post

The `pure` script maps to the `astro-pure` CLI, so a new article is one command away:

```bash
bun pure new
```

The CLI scaffolds the Markdown file and its folder under `src/content`. Fill in the front matter and write the body. Everything else, including the OG image at build time, follows from that file.

## Step 2: Configure the Site Before the First Build

Almost all site settings live in `src/site.config.ts`. Open it and change:

- The site title and description
- Author name, avatar, and bio
- Social links
- Navigation items in the menu array
- Theme color and appearance options

Do this before you deploy. A first deploy that still says "Astro Theme Pure" in the header and links to `astro-pure.js.org` is the most common thing people forget, and crawlers pick up the wrong metadata immediately.

If you plan to use a base path at all, note that the menu entries in this file are one of the places the theme expects patched. More on that in step 4.

## Step 3: Switch Astro Theme Pure to Static Output

Open `astro.config.ts`. The default configuration imports the Vercel adapter and sets server output:

```ts
import vercel from '@astrojs/vercel'

export default defineConfig({
  site: 'https://astro-pure.js.org',
  adapter: vercel({ imageService: true }),
  output: 'server',
})
```

Remove the import, remove the adapter line, and set `output` to `static`. Also replace `site` with your final public URL:

```ts
export default defineConfig({
  site: 'https://YOUR_USERNAME.github.io',
  output: 'static',
  // adapter line removed
})
```

Leave `trailingSlash: 'never'` as it is. GitHub Pages serves extensionless paths from matching `.html` files, so `/p/hello` resolves to `p/hello.html` without any rewrite rule.

One detail that trips people up: `imageService: true` was a runtime feature of the Vercel adapter. With static output, Astro optimizes images at build time instead, using the `sharp` package the template already installs. Nothing breaks, but images are processed during the build rather than on request, which is why a large photo folder makes the build slower.

Build locally to confirm the switch worked:

```bash
bun run build
```

The site appears in `dist/`. Preview it with `bun preview` and click through the navigation before you push.

## Step 4: Choose Your GitHub Pages URL Before You Deploy

GitHub Pages gives you three kinds of address, and the choice affects the config more than people expect.

| Address type | Example | `site` | `base` |
|---|---|---|---|
| User or organization site | `username.github.io` | `https://username.github.io` | omit |
| Project site | `username.github.io/repo-name` | `https://username.github.io` | `/repo-name` |
| Custom domain | `blog.example.com` | `https://blog.example.com` | omit |

The project site column is the one that hurts. The theme's own deployment documentation warns that it does not support a base path and that deploying the template this way is not recommended, because the homepage layout depends on root-relative paths. If you go ahead, the docs list the files that need patching:

- `src/components/BaseHead.astro`
- `src/pages/docs/DocsContent.astro`
- `src/pages/rss.xml.ts`
- `packages/pure/components/pages/PostPreview.astro`
- Menu entries in `src/site.config.ts`
- Icon paths in `src/plugins/shiki-transformers.ts`
- Font URLs in `src/assets/styles/app.css`

That is a lot of files to keep patched every time you pull upstream changes. If the site is yours and the content is a blog, name the repository `YOUR_USERNAME.github.io`. The site then lives at the root, `base` stays unset, and every path in the theme works without editing. If you want a nicer name, register a custom domain instead. Our [GitHub Pages custom domain guide with Cloudflare](/p/github-pages-custom-domain-cloudflare/) walks through the DNS side, and the same steps apply here.

Pick the root URL or a custom domain when you can. A project site means maintaining a patch list forever, and that cost lands every time you update the theme.

## Step 5: Deploy Astro Theme Pure with GitHub Actions

Create the repository on GitHub and push your project:

```bash
git remote add origin https://github.com/YOUR_USERNAME/YOUR_REPO.git
git branch -M main
git push -u origin main
```

Then add `.github/workflows/deploy.yml`:

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v7

      - name: Install, build, and upload site
        uses: withastro/action@v6
        # with:
        #   node-version: 22
        #   package-manager: bun@latest
        #   build-cmd: bun run build

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v5
```

Three things in that file are load-bearing:

1. `id-token: write` and `pages: write` must stay. Pages deployments authenticate with an OIDC token, and removing either permission produces an authorization failure that reads like a bug in the action.
2. The action detects your lockfile, so a committed `bun.lock` means Bun runs in CI. If you installed with npm, commit `package-lock.json` and leave the inputs alone.
3. `workflow_dispatch` lets you re-run a deploy without an empty commit.

If you already followed a manual Astro deployment, this workflow replaces it. Our [general Astro to GitHub Pages walkthrough](/p/how-to-deploy-astro-github-pages/) explains the same action for a plain Astro project, which is useful if you strip the theme later.

## Step 6: Enable Pages and Check the Deploy

In the repository, open **Settings → Pages** and set **Source** to **GitHub Actions**. That is the only repository setting required.

Push a commit or trigger the workflow manually. When both jobs finish, the site is live at your chosen URL.

Then verify the paths instead of assuming they work. Open the site, press F12, and reload with the network panel open. Every CSS, JS, font, and image request should return 200. A single 404 on `/_astro/...` means the asset base is wrong, and it usually shows up as an unstyled page rather than an error message.

Search is worth checking too. Click the search box and type a word from one of your posts. If nothing appears, the Pagefind index was not built, which almost always means the deploy ran a dev build or the build step was skipped.

## What We Found Before Writing This Guide

Before publishing, we cloned the repository at 4.1.6 and read `astro.config.ts`, `package.json`, and the deployment page of the theme docs rather than trusting older tutorials. Three things stood out.

First, many existing guides still say Node 18 is enough. That is no longer true. The template pins Astro 6.4.8, and Astro 6 requires Node 22.12.0 or newer, with a warning that odd-numbered releases are unsupported. Builds fail on Node 18 before they reach your code.

Second, the Vercel adapter is not optional decoration. It is imported at the top of the config and enabled with `output: 'server'`. You need to remove both lines, not just toggle the output value.

Third, the theme documentation is unusually blunt about base paths. It states that the theme will not support them and that you proceed at your own risk. That warning is worth reading before you start patching files, because the alternative is one line of repository naming.

That third point is also the honest limitation of this guide. If a project site is non-negotiable, expect to maintain a patch list and re-check it after every theme update.

## Common Pitfalls and Fixes

| Symptom | Likely cause | Fix |
|---|---|---|
| Homepage loads, inner pages 404 | Base path missing or malformed | Set `base: '/repo-name'`, rebuild, and confirm links use it |
| Page renders without styles | `/_astro/` assets requested from the root | Same base path issue, plus check the components listed in step 4 |
| Build fails on the Vercel adapter | Adapter import left in place | Remove the import and the adapter line, keep `output: 'static'` |
| Search returns nothing | Pagefind index never built | Run a production build, then check the deploy log for the index step |
| Sitemap or RSS points at the wrong host | `site` still set to the demo URL | Set `site` to the final public URL and redeploy |
| Fonts missing | Font URLs in `app.css` still root-relative | Patch them when using a base path, or avoid the base path |
| Deploy job fails with an authorization error | Permissions block missing or edited | Restore `pages: write` and `id-token: write` |

## SEO Setup That Comes Free, and What You Still Own

The theme covers the mechanics: sitemap, RSS, canonical URLs, and per-post Open Graph images are generated at build time. That is more than most themes give you.

What it cannot do is know your site. Three settings remain yours:

- `site` in `astro.config.ts` must be the final URL, including the custom domain if you use one. Every canonical tag and sitemap entry derives from it.
- The `description` field in each post front matter becomes the meta description. Write it for the search result, not for the build log.
- Images need alt text. Static hosts serve whatever you ship, and accessibility does not come from a theme.

If you want a deeper checklist for the content side, our [Hugo SEO guide](/p/hugo-seo-guide/) covers metadata and structured data in a way that transfers to Astro almost line for line.

Blog design choices around images are worth a look too. The theme uses a lightbox, and readers on a slow connection still pay for whatever you upload, so compress before you commit. The habits in our notes on [image galleries in Dev9b articles](/p/image-gallery-in-dev9b-articles/) apply here as well.

If you would rather not run GitHub for this, the build output is plain static files. [Hosting a static site on Codeberg Pages](/p/how-to-host-static-websites-codeberg-pages/) uses the same `dist/` folder with a different remote.

## FAQ

### Do I need Bun to use Astro Theme Pure?

No. The maintainers recommend Bun and the repository ships a `bun.lock` file, but npm, pnpm, and yarn all install and build the theme. The `withastro/action` workflow detects your lockfile and picks the matching package manager.

### Why does Astro Theme Pure default to a Vercel adapter?

The template ships with `@astrojs/vercel` and `output` set to `server` so the hosted demo works on Vercel. GitHub Pages only serves static files, so you remove the adapter import, the adapter line, and set `output` to `static`.

### Can I deploy Astro Theme Pure to a project site at username.github.io/repo-name?

Technically yes, but the theme documentation warns that a base path breaks parts of the template and lists the files you must patch. A user site at `username.github.io` or a custom domain avoids the problem entirely.

### Can I use a custom domain with GitHub Pages?

Yes. Add a `CNAME` file containing your domain to the `public` folder, set `site` in `astro.config.ts` to the full custom URL, and remove the `base` option. Then point DNS at GitHub following their documented records.

### How do I update Astro Theme Pure later?

If you cloned the repository, pull upstream commits and resolve conflicts in `src/site.config.ts` and `astro.config.ts`. New projects can install the theme integration from the `astro-pure` npm package instead of copying the template.

## Key Takeaways

- Astro Theme Pure gives you search, sitemap, RSS, and generated OG images out of the box, which is most of the SEO plumbing already done.
- You must remove the Vercel adapter import and set `output: 'static'` before GitHub Pages will build a working site.
- Prefer a user site or a custom domain. The theme docs warn that a base path breaks parts of the template and list seven files to patch.
- Use `withastro/action@v6` with `actions/deploy-pages@v5`, and keep the `pages: write` and `id-token: write` permissions.
- Verify assets in the browser network panel after the first deploy instead of assuming the base path is right.

## Conclusion

Installing Astro Theme Pure is a short job: clone, install, edit `src/site.config.ts`, drop the Vercel adapter, and push a workflow. The part worth slowing down for is the URL decision. Pick a root address or a custom domain, and the theme works as designed. Pick a project site, and you inherit a patch list that grows with every update.

That trade-off is the same one static sites always make. Free hosting is genuinely free, but the path structure is part of the deal.
